# Cross-Repository Compatibility

This matrix records the Hub source snapshot and its compatibility assumptions with Vault v0.2. A successful local build or CI run does not prove live network compatibility.

**Reviewed source snapshots:** Hub `7d8476c49b8d2b705ce4c6a4fdd7e30e82adb943` (after Dependabot PRs #62–#67); Vault v0.2 `f70c1a225b58288b941ab144f17859cc3df036f9`. Current public contracts and cutover evidence are for Stellar Testnet Protocol 29. A live `getNetwork` query to the Testnet Soroban RPC returned `protocolVersion: 29` on 2026-11-03 at 07:45 UTC, before the announced 17:00 UTC Testnet vote. Protocol 30 compatibility is not claimed here.

## Protocol 30 status

The vote had not yet occurred at the time of the dated RPC check, so its outcome and any later activation are **DEFERRED**. Protocol 30-specific compatibility remains **UNVERIFIED**. In particular, this matrix does not assert support for muxed contract `W` addresses or Protocol 30 raw-ledger XDR changes. Recheck `getNetwork` after the vote and activation, then test JavaScript and Go SDK behavior, Freighter address handling, indexer decoding/checkpoint replay, and watcher RPC behavior before updating this status. The [SDF announcement](https://stellar.org/blog/developers/introducing-bell-protocol-30-on-stellar) schedules the Testnet vote for 2026-11-03 at 17:00 UTC; see also the [Stellar Protocol 30 upgrade guide](https://stellar.org/blog/developers/bell-protocol-30-upgrade-guide).

The [September 29 parity matrix](https://github.com/SLASettleHQ/slasettle-hub/blob/main/evidence/parity-matrix-2026-09-29.md) is retained as historical evidence. Use current source, lockfiles, tests, and dated v0.2 evidence for present compatibility claims.
